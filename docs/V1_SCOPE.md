## 0. まず削除すべきプロセス — 「徹底的に調査する」という要件

Musk の第1ステップは「要件を疑え。要件には人の名前を付けろ (部署名ではなく)」。
このリポジトリで最も疑うべき要件は、機能ではなく**プロセス**だった。

| | 変更量 |

**比率 20:1 で文書。新規の製品能力はゼロ。**

## 1. 要件を疑う — 製品定義の各語を証拠に照らす

製品定義: **「他人のアイドル GPU を、安全に、1 ドル未満で 60 秒借りる」**

| 語 | 対応公理 | 証拠 | 判定 |
|---|---|---|---|
| **他人の** | A1 発見 | Iroh の mDNS は**リレー不要でデフォルト有効** (§4d)。NAT 越えが難所であって、発見自体ではない | **縮小して残す** — v1 は **LAN のみ** |
| **安全に** | A6 秘匿 | 消費者 GPU に CC が無い (W4)。Rope の短ジョブ形状で **13-27% のスループット損** (A6⊥A8)。貸し手を法的に盲目にする (A6⊥A9)。gVisor はゼロコンフィグを壊す (A9⊥A8) | **🔴 v1 から削除** — 下記 §2 |
| **1 ドル未満** | A5 経済 | 電力コスト **$0.001-0.04/100万トークン**、クラウドの **40-200 倍安**、4ヶ月で回収 (§4g) | **残す** — 疑う理由が無い |
| **60 秒** | A8 体験 | cold start 実測 40 秒超。**ウォームな貸し手 + 小型モデルが前提** (§4f)。デモは既に 1B 級 | **残す。ただし前提を明記する** |

### 🔴 最大の発見: A6 は 4 つの構造的緊張のうち **3 つ**に関与している

- `A6 ⊥ A8` (性能): CC のオーバーヘッドは**小さく短いジョブで最大化**する — Rope の形状そのもの
- `A6 ⊥ A9` (法務): 秘匿を完全にするほど貸し手は違法生成を検知できず「緩和を怠った」責任を負う
- `A9 ⊥ A8` (隔離): GPU 呼び出しに介在できる gVisor は導入が要り、ゼロコンフィグを壊す
- (`A9 → A7` だけが A6 と無関係)

**一つの要件が、他の要件との衝突の大半を生んでいる。これが「dumb requirement」の signature。**
しかも **W4 は解消していない** — 消費者 GPU (供給プールの主体) に CC は来ていない。

## 2. 削除する — v1 に入れないもの

> Musk: 「削除したものの 10% を戻していないなら、削り足りない」

| 削除するもの | 理由 | どこへ | 状態 |
|---|---|---|---|
| **A6 (TEE 秘匿) 全体** | 上記。消費者 GPU で成立せず、3 つの緊張の源 | v2 | 📄 スコープ決定のみ (コードは温存 — 下記) |
| **`Workload::Train`** | 借り手指定 URI のフェッチ = SSRF 面 (§1.11)。借り手指定 `base_model` のロード = **pickle RCE 面** | v2 | ✅ **削除実施** (2026-08-18) |
| **`Workload::Retrieve`** | v1 に corpus 管理を入れる価値が無い | v2 | ✅ **削除実施** (2026-08-18) |
| **A4 (実行検証)** | **A3 が無い今、検証する対象が存在しない**。加えて Hollow-LLM は推奨手法が Rope の脅威モデルに合わない可能性を示した (§1) | v2 | 📄 未実装なので削除対象コード無し |
| **NAT 越え / リレー** | LAN に限れば不要 (§4d)。**最大の難所を要件から外す** | v2 | 📄 未実装なので削除対象コード無し |
| **A2 の Sybil 耐性 (`CapabilityChallenge`)** | LAN では相手は「同じネットワークに居る人」= TOFU で足りる。Sybil は地球規模の要件 | v2 | 📄 型は温存 (下記) |
| **`format_*` 6 個・QR/TOFU 統計 7 個** | どの公理にも対応しない (監査 §3) | — | ✅ **処理済** (3 結線 / 2 削除 / 1 延期 — `SURPLUS_AND_GAPS.md` §1.7) |

### 「削除」と「スコープから外す」を区別する

A6 (TEE) と Sybil 耐性は **v1 のスコープからは外すが、コードは消していない**。
理由は 2 つ:

1. **v1 が動くために消す必要がない。** `Train`/`Retrieve` を消したのは
   *攻撃面が消えるから*であって、行数が減るからではない。A6 のコードは
   借り手入力を一切受け取らないので、残っていても v1 の攻撃面を広げない。
2. **ビルド不能環境で消すのは危険。** `confidential.rs` は 1,472 行あり、
   `first_run.rs` の attestation ステップと双方向に絡む。コンパイラ無しで
   その規模の削除をやると、過去に 1 度やらかした
   `perform_attestation`/`update_stats` 回帰 (`CLAUDE.md` 規範2) の再演になる。

→ **A6 のコード削除は「CI が動くようになってからの作業」として残す。**
スコープ文書 (本書)・`SECURITY.md`・`README.md` は既に v1 の約束から A6 を
外してあるので、**ユーザーに対する約束の面では削除は済んでいる。**

### `Train`/`Retrieve` を切ると、脅威が丸ごと消える

これが最も効く削除。`Workload::Inference` は **プロンプトのみ**を運ぶ。
`Train`/`Retrieve` を v1 から外すと:

- **SSRF 面が消える** (借り手指定 URI が存在しなくなる)
- **pickle RCE 面が消える** (借り手指定 `base_model` が存在しなくなる)
- → §1.11 で「A9 の絶対条件」とした 2 つの制約が、**実装ではなく削除で満たされる**

**機能を足して防御するのではなく、機能を消して攻撃面を消す。**

## 3. 残るもの — v1 の定義

> **LAN 上の他人の GPU で、プロンプト推論を、トークン不要の ecash で払って、
> 設定ゼロで走らせる。**

v1 が必要とする公理:

| 公理 | v1 での範囲 | 現状 |
|---|---|---|
| **A1** 発見 | **LAN のみ** (mDNS)。NAT 越え無し | ✅ **発見も転送も実装済 (2026-08-18)**。⚠️ **暗号化のみ未実装** — 既定で無効、明示的 opt-in が要る |
| **A2** 信頼 | **TOFU のみ** | 実装済み |
| **A3** 実行 | **プロンプト推論のみ**、ローカルモデルパス、CPU | ✅ **実装済 (2026-08-18)** — `src/net/inference.rs`、依存ゼロ、テスト 22 件が実際に走る |
| **A5** 対価 | ecash + DLEQ でオフライン検証 (§4c) | 🔶 **配線済 (2026-08-18)** — token は実際に渡る。⚠️ **BDHKE がプレースホルダなので実 mint では通らない** (`k256` 待ち)。DLEQ 未実装 |
| **A7** 中断耐性 | deadman 返金 + **`A9→A7` の接続** (§1.10) | ✅ **実装済 (2026-08-18)**。`panic_stop` の呼び出し元 (シグナルハンドラ) のみ未配線 |
| **A8** ゼロコンフィグ | 現状維持 | **✅ 動く** |
| **A9** 貸し手保護 | **プロセス隔離のみ** (pure Rust crate)。GPU レベルは**保護しないと開示** | 🔶 **攻撃面の除去は実装済** (外部コード非ロード・ヘッダ検証・パス無害化・計算量上限)。**プロセス隔離は未実装** |

v1 が**必要としない**公理: **A4 / A6**。

### なぜこれが出荷可能か

- ~~**A3 以外は全て「実装済みか、状態機械があって配線するだけ」**~~ →
  **2026-08-18 時点: A1・A3・A5 の配線が全て通った。**
  「LAN 上の他人のマシンでプロンプト推論を走らせ、トークン不要の bearer token で
  払う」は**エンドツーエンドで動く** (平文・opt-in)。
  **残るのは配線ではなく中身**:
  - 🔴 **BDHKE がプレースホルダ** — 渡っているトークンは実 mint では通らない
    (`k256` が要る、§1.1)。**これが v1 と「本当に新しい製品」の間に残る唯一の壁。**
  - 🔴 **暗号化が無い** — 転送は平文 (`snow` が要る、§1.1)
  - 価格交渉が無い (暫定の固定規則、§1.12)
  いずれも**新規 crate がこの環境に入らないことだけ**が理由であり、
  設計や実装量の問題ではない。
- **A9 が `Inference` のみなら大幅に軽い** — SSRF も pickle も無い。
  pure Rust の隔離 crate (`sandbox-rs` 等) で足り、gVisor 導入が要らない
  → **`A9 ⊥ A8` が消える**。
- **A6 を切ったので `A6 ⊥ A8` と `A6 ⊥ A9` も消える**。
  → **4 つの構造的緊張のうち 3 つが、削除だけで消滅する。**

## 4. v1 で守る「唯一の差別化」

調査した競合は**すべて独自トークン**で決済する (TON/NOS/AKT/IO)。
**ecash や Lightning で決済する GPU マーケットは見つからなかった** (§4k)。

→ **v1 が証明すべき固有価値は「トークン不要の少額決済で計算が買える」**。
A1 (発見) も A3 (推論) も競合が既に出荷している能力であり、そこで勝つ必要はない。
**LAN 1 台でも、no-token で払えて実際に推論が返れば、それは誰も出荷していない。**

## 5. 実装順序 (③単純化・④高速化・⑤自動化はこの後)

Musk の順序を守る。①②が終わったので、ここから作る:

1. ~~**A3: プロンプト推論を実際に走らせる**~~ → ✅ **2026-08-18 実装完了**
   (`src/net/inference.rs`)。**ただし mistral.rs は使わなかった** — 提供するのは
   GPU カーネルと速度であって「実行できる能力」ではないため。**依存ゼロ**の
   Transformer を書いた結果、**この環境でもテストが実際に走る** (22 件 PASS)。
   A9 は「隔離」ではなく「攻撃面の除去」で満たしている (外部コードを読まない +
   ヘッダ検証 + パス無害化 + 計算量上限)。**プロセス隔離は未実装** — v2。
   **残る「他人の」部分は下記 2・3 のまま**。
2. 🔶 **A5 を `rope run` に結線** → **配線は 2026-08-18 完了**。
   bearer token が実際にワイヤを渡り、貸し手のウォレットに入る
   (`Message::Payment`、テスト 2 件が実ソケットで PASS)。
   ⚠️ **ただしトークン自体はまだ本物ではない** — `build_proof` は §1.1 の
   プレースホルダのままで、**実 mint なら拒否される**。`k256` が要る。
   **DLEQ (NUT-12) も未実装。** 価格交渉メッセージも無く、暫定の固定規則
   (1 出力トークン = 1 sat) で動いている (§1.12)。
3. ✅ **A1: LAN のピア発見と転送 — 2026-08-18 実装完了**
   (`src/net/mdns.rs` / `wire.rs` / `transport.rs`、テスト 26 件が実走)。
   **Iroh は使わなかった** — 提供するのは NAT 越え・リレー・QUIC で、
   NAT 越えは本書 §2 で既に v1 から削除済みだった。
   **ジョブは実際に TCP を渡り、貸し手側で実行されて返る。**
   ⚠️ **暗号化だけが無い** — Noise は §1.1 が「検証済み crate 無しで手書きするな」
   と定めており、この環境に `snow` を追加できない。転送は
   **既定で無効**で、`ROPE_ALLOW_PLAINTEXT=1` の明示が要る。
4. ✅ **A7 の `A9→A7` 接続 — 2026-08-18 完了** (§1.10)。`panic_stop` が未完了 escrow を返金する。完了済みは `refund_escrow` の既存ガードで除外され、claw-back 攻撃は成立しない。**残るのは `panic_stop` の呼び出し元** (シグナルハンドラ未配線)。
5. ここまで来て初めて **③単純化 / ④高速化 / ⑤自動化 (CI)**。

**④より前に⑤ (CI 有効化) をやらない** — 動くものが無い段階の自動化は、
Musk が名指しで戒める順序違反。

### ②の後始末と③の本番を混同しない (2026-08-18 追記)

2026-08-18 に `src/` へ入れた変更 (`Train`/`Retrieve` 削除、`format_*` の
結線と削除) は、**③「単純化」の本番ではなく②「削除」の後始末**である。
②で「要らない」と決めたものを実際にコードから消し、消した結果ぶら下がった
重複整形を 1 箇所へ寄せただけ。**まだ存在しない A3 のコードを最適化しては
いない** — それをやったら Musk が名指しする「存在すべきでないものの最適化」
そのものになる。

③の本番 (推論パスの最適化・cold start 短縮) は **A3 が動いてから**。
順序は上の 1→5 のまま変わらない。

## 6. この決定が意味すること (正直な記載)

- **README の約束は縮む。** 「TEE プライバシー」は v1 の売り文句から外れる。

  1 割程度出るのが健全。**1 つも戻らないなら削り足りない。**
